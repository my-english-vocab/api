# 첫 단어장 온보딩 API

인증된 계정의 첫 단어장을 만드는 선택형 입문 과정이다. DB 마이그레이션, 외부 AI 호출, 새 환경 변수는 없다. 기존 `words` 테이블 및 `WORD_CREATED` 활동 기록을 사용한다.

| API | 역할 |
| --- | --- |
| `GET /api/onboarding/status` | 현재 계정의 단어가 0개이면 `{"eligible":true}` 반환 |
| `GET /api/onboarding/catalog` | 카탈로그 버전과 목적별 단어·뜻·예문·번역 반환 |
| `POST /api/onboarding/complete` | 선택한 ID에 해당하는 원본 단어를 한 트랜잭션으로 저장 |

저장 요청 예시:

```json
{"version":3,"trackId":"toeic","wordIds":["toeic-schedule","toeic-invoice"]}
```

응답 예시:

```json
{"addedCount":2,"existingCount":0}
```

- 소유자는 요청의 사용자 ID가 아니라 인증 토큰에서 결정한다.
- 카탈로그 버전, 목적, 최대 10개 ID, ID의 목적 소속, 중복 ID를 검증한다. 뜻·예문은 클라이언트에서 받지 않는다.
- 빈 선택은 허용한다. 프론트엔드는 0개 선택 시 API를 호출하지 않고 끝낼 수 있다.
- 계정 행의 쓰기 잠금으로 같은 사용자의 온보딩 완료 요청을 직렬화한다. 이 과정에서 기존 단어의 앞뒤 공백과 대소문자를 무시해 비교하고 중복은 건너뛴다.
- 이미 있는 단어의 내용·암기 레벨·즐겨찾기는 변경하지 않는다. 새 단어는 기존 규칙대로 레벨 0으로 생성한다.
- 여러 단어 저장과 활동 기록은 동일 트랜잭션에 포함되므로 저장 중 실패 시 함께 롤백된다.
- 온보딩의 잠금은 온보딩 요청 사이의 중복을 막는다. 기존 일반 단어 CRUD에 전역 유일성 제약을 추가하지 않는다.
- 완료/건너뛰기 여부나 테스트 응답은 DB에 저장하지 않는다. 단어 0개 사용자의 다음 로그인 재안내는 프론트엔드 세션 정책으로 처리한다.

## 콘텐츠 수정

`src/main/resources/onboarding/catalog.json`을 편집한다. 목적은 토익(`toeic`), 수능(`csat`), 일상·여행(`daily`), 토플·학술(`toefl`), 오픽·말하기(`opic`), 비즈니스 이메일(`business-email`), IT·개발 문서(`it-dev`)의 7개이며 각각 초급 2 / 중급 3 / 고급 5, 10개씩, 전체 70개다. 버전 2의 기존 3개 목적·30개 단어는 그대로 유지했다. 직접 작성한 입문용 예문이며 공식 기출·빈도 순위·점수 환산 자료가 아니다.

내용이나 ID를 변경하면 `version`을 올린다. 현재 버전은 3이며, 변경된 JSON은 백엔드를 재시작해야 반영된다. 이미 사용자 단어장에 저장된 단어는 자동 변경되지 않는다. 단어 ID는 목적 안에서 고유해야 하며 각 단어에 뜻, 영어 예문, 한국어 해석이 있어야 한다. 콘텐츠 테스트가 개수·난이도 구성·필수 값·DB 길이 제한을 확인한다.

## 검증

Java 21에서 `./gradlew test` 실행. `OnboardingApiTest`는 카탈로그 품질 조건, 인증, 계정 분리, 선택 저장, 기존 내용 보존, 잘못된 요청, 재시도, 실제 병렬 완료 요청을 검증한다.

자동 테스트와 로컬 브라우저 확인은 H2 기반이다. 운영 PostgreSQL·Redis·외부 배포 환경 검증은 별도로 필요하다.

콘텐츠 확장 요청에는 [ChatGPT용 프롬프트](onboarding-content-prompt.md)를 사용할 수 있다.
