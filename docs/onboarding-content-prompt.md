# ChatGPT에 전달할 온보딩 콘텐츠 확장 프롬프트

아래는 카탈로그 버전 2를 3으로 확장할 때 사용한 프롬프트입니다. 결과는 현재 7개 목적·70개 단어로 반영했습니다. 다시 확장할 때는 현재 `catalog.json`을 첨부하고, 아래의 기존 목적 목록을 7개 전체로, 요청 버전을 4로 수정해 사용하세요.

````text
한국인 영어 학습자를 위한 단어장 앱의 온보딩 콘텐츠를 설계해 줘.

[서비스와 목표]
- 사용자는 학습 목적을 선택한 뒤 영어 단어 10개를 한 개씩 확인한다.
- 영어 예문은 처음부터 보이고, 단어 뜻과 한국어 예문 해석은 펼쳐서 확인한다.
- 사용자는 “알고 있어요” 또는 “모르겠어요”로 답한다.
- 결과에서 모르는 단어를 기본 선택하고, 원하는 단어만 개인 단어장에 저장한다.
- 목적은 실력 등급 판정이 아니라, 실제로 공부할 가치가 있는 낯선 단어를 발견하고 첫 단어장을 만드는 것이다.

[학습 목적]
- 기존 목적 3개를 유지한다: 토익(toeic), 수능 영어(csat), 일상·여행 영어(daily).
- 여기에 서로 구분되는 목적 3~5개를 제안하고 콘텐츠를 작성한다. 예: 토플·학술 영어, 오픽·영어 말하기, 비즈니스 이메일, IT·개발 문서 읽기.
- 사용자가 선택하기 쉽게 각 목적의 대상과 학습 상황을 명확히 구분한다. 지나치게 겹치는 목적은 합친다.
- 첨부한 기존 데이터가 있다면 유용하고 정확한 항목과 ID는 유지한다. 바꿔야 할 항목은 변경 이유를 따로 설명한다.

[목적별 단어 선정]
- 각 목적에 정확히 10개: beginner 2개, intermediate 3개, advanced 5개.
- 배열 순서는 초급 → 중급 → 고급으로 한다.
- 초급은 시작의 부담을 낮추는 익숙한 단어, 중급은 해당 분야에서 자주 접할 법한 핵심 단어, 고급은 학습 가치가 높으면서 일반 학습자가 놓치기 쉬운 단어로 고른다.
- 단어장 저장 개수를 늘리려고 희귀어·고어·과도한 전문용어를 억지로 넣지 않는다. 고급도 해당 목적에 실용적이어야 한다.
- 난이도는 한국인 학습자를 가정한 편집상 분류다. 근거 없는 공식 난이도·필수 어휘·출제 빈도·점수 환산을 주장하지 않는다.
- 분야 안에서는 단어를 중복하지 않는다. 분야 간 중복도 가능한 한 줄이되, 학습 가치가 높다면 이유를 설명한다.
- 표제어 중심으로 선택하고, 예문에서는 자연스러운 활용형을 허용한다.

[뜻과 예문 품질]
- definition은 예문에서 쓰인 의미를 우선하는 간결한 한국어 뜻으로 작성한다.
- exampleSentence는 해당 학습 목적의 실제 상황에 맞는 자연스러운 영어 문장 한 개다. 권장 길이는 8~18단어이며, 자연스러움이 우선이다.
- 목표 단어 이외의 어휘·문법은 비교적 쉽게 쓴다. 목표 단어의 뜻을 영어로 직접 풀이하는 문장은 피한다.
- meaningOfExampleSentence는 영어 예문의 시제·주체·조건을 보존한 자연스러운 한국어 번역으로 작성한다.
- 사전·교재·시험 기출의 예문을 복사하지 말고 직접 작성한다.
- 가능하면 신뢰할 수 있는 학습자 사전으로 의미·품사·결합 표현을 확인한다. 확인하지 못한 내용은 검증했다고 말하지 않는다.

[앱이 읽는 JSON 형식]
- 최상위 구조: {"version": 3, "tracks": [...]}.
- track의 필드는 id, title, subtitle, description, words만 사용한다.
- id: 고유한 영문 소문자 식별자, 필요 시 하이픈, 최대 30자.
- title: 한국어 목적 이름. 모바일에서 읽기 쉽게 간결하게 작성한다.
- subtitle: 짧은 영문 표시명.
- description: 사용자가 무엇을 배우는지 설명하는 짧은 한국어 문장.
- word 필드는 아래 예시의 6개만 사용한다.
- word id는 “목적ID-표제어” 형태의 고유 식별자로, 최대 50자.
- difficulty는 beginner, intermediate, advanced 중 하나.
- term 최대 100자, definition 최대 150자.
- exampleSentence와 meaningOfExampleSentence는 각각 최대 1,000자.
- 모든 필드는 빈 값 없이 채운다. 주석, 후행 쉼표, 생략 표시 없이 실제 파싱 가능한 완성 JSON을 제공한다.

단어 객체 형식 예시(형식 설명용이며 선정 단어로 강제하지 않음):
```json
{
  "id": "toeic-procurement",
  "difficulty": "advanced",
  "term": "procurement",
  "definition": "조달, 구매",
  "exampleSentence": "The procurement team compares prices before choosing a supplier.",
  "meaningOfExampleSentence": "조달팀은 공급업체를 선택하기 전에 가격을 비교합니다."
}
```

[응답 순서]
1. 목적별 대상과 선정 이유를 짧은 표로 제시한다.
2. 모든 목적과 단어가 포함된 단일 완성 JSON 코드 블록을 제공한다. 생략하지 않는다.
3. JSON 밖에 검수 결과를 적는다: 목적별 10개인지, 난이도 2/3/5인지, ID·단어 중복, 뜻과 번역의 대응, 분야 간 중복 이유, 실제 확인한 출처와 미확인 사항.
4. 첨부 데이터에서 기존 단어를 바꿨다면 변경 목록을 덧붙인다.

앱 코드나 추가 기능은 작성하지 말고, 위 구조에 바로 적용할 수 있는 학습 콘텐츠에 집중해 줘.
````

## 적용 전 참고

생성 결과를 검토한 뒤 `src/main/resources/onboarding/catalog.json`에 반영합니다. 새 목적을 실제로 추가할 때는 백엔드 테스트의 목적 개수 조건(현재 7개)과 프론트엔드 목적 카드 아이콘도 함께 검토해야 합니다. JSON은 서버 시작 시 읽으므로 실행 중인 백엔드는 재시작해야 하며, 이미 사용자의 단어장에 저장된 단어는 자동 변경되지 않습니다.
